# GTA PS1

Free-roam driving game in a US city (California / Los Angeles vibe) with a PlayStation 1 art direction:
pixelated low-res textures, simple low-poly shapes, but modern-ish lighting (sun + hard shadows), fog and a
few post effects. Code name "GTA"; the scope is driving freely in a fairly open world, not a full GTA.
Talk to Fabien in French.

## Stack

- Unity 6000.0.85f1, URP 17, **Input System only** (`activeInputHandler: 1` → use `Keyboard.current`/`Gamepad.current`).
- Blender 5.1 driven through the Blender MCP: all world geometry is generated by Python in `Tools/`.
- Images: ChatGPT image generation through Playwright (Fabien logs in himself), converted by `Tools/texture/ps1ify.py`.
  NPC atlas region edits go through the muware `gpt_image_edit` MCP instead (exact output size, see skill `ps1-npc`).
- Unity MCP for editor automation (`Unity_RunCommand` with `internal class CommandScript : IRunCommand { public void Execute(ExecutionResult result) { result.Log(...); } }`;
  `Unity_ReadConsole` with `filterText`, its `types` parameter is broken).

## Skills (read them before working in their area)

- `city-roadnet` – roads, junctions, highway, ramps, blocks: how to edit, standards, verification.
- `ps1-art-direction` – texel density (16 px/m, 1 UV = 4 m), realistic sources degraded by ps1ify, budgets, look rules.
- `chatgpt-images` – generating and converting images with ChatGPT.
- `ps1-npc` – pedestrians: hero.fbx base, atlas variants (AI region edits), female body, mocap clips, prefabs, placement.
- `city-traffic` – traffic: lane graph export, TrafficSystem (instanced cars, junction rules, proxies, wrecks), car paints, verification.

## Conventions

- Meters everywhere. Blender is Z-up; FBX export uses `axis_forward='-Z', axis_up='Y', bake_space_transform=True`
  so Unity objects come in with identity transforms. Drive on the right.
- Material names are the contract between Blender and Unity: Blender material `Foo` → Unity uses
  `Assets/GTA/Textures/T_Foo.png` if it exists (see `ImportRules.cs`). Keep names stable.
- Geometry is regenerated, never hand-edited: change the Python, rebuild, re-export, then run PropPlacer on the scene.
- No placeholders: every object comes with its own coherent textures; repeated objects are prefabs (see ps1-art-direction).
- Every mesh carries vertex colors (white by default, darkened for grime/AO) – the PS1Lit shader multiplies them.
- Playwright downloads (`browser_evaluate` with `filename`) land in the project root: move them to the scratchpad.
  `.playwright-mcp/` (project root) is Playwright's scratch output – never reference it.
- Delete the ChatGPT conversations you created once the images are downloaded (Fabien's request).
- Cars: `cars.export_car('W123i')` (front axis given by `front_axis`, default +X) turns the car to Unity +Z,
  bakes rotations, keeps wheel objects at the wheel centers, copies the atlases to `T_<material>.png`, renames
  semi-transparent materials `<atlas material>__Glass` (blended by ImportRules). In the prefab, `SimpleCar.wheels`
  point at the model's wheel objects (rest position = wheel centers; suspension mounts are derived).
- Blender: `Tools/citygen` modules are imported via `sys.path`; always `importlib.reload` roadnet, kit, city_demo,
  da_scene before building. The City and DA collections live in the same .blend scene (exclude one when rendering).
- Blender → Unity axes: Unity = (−x, z, −y) of Blender (180° turn, not mirrored).

## Working with Unity via MCP

- Fabien may be playing in Play mode: don't stop Play mode or move the car without asking.
- To drive from MCP: `PlayerSettings.runInBackground = true` (already set) and
  `InputSystem.settings.backgroundBehavior = IgnoreFocus`, then `InputSystem.QueueStateEvent(Keyboard.current, new KeyboardState(Key.W))`.
- Screenshots: render `Camera.main` into a RenderTexture and save a PNG (Unity_Camera_Capture fails in Play mode).
